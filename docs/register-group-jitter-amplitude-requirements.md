# 寄存器组抖动幅度需求文档

## 1. 需求背景
- 为更真实模拟现场设备数据波动，需要在寄存器组层面支持统一的数据抖动能力。
- 当前寄存器组缺少可配置的动态波动参数，无法表达“轻微随机变化”的数据特征。

## 2. 需求目标
- 在每个寄存器组新增参数：`jitterAmp`（抖动幅度）。
- 支持前端配置、保存该参数。
- 在读取该寄存器组寄存器值时，由后端按规则动态抖动返回值。

## 3. 功能范围
- 后端：模型字段、接口入参/出参、读取数据逻辑、配置持久化。
- 前端：寄存器组新建/编辑页面支持配置该参数。
- 兼容历史配置：旧数据无该字段时按默认值处理。

## 4. 字段定义
- 字段名：`jitterAmp`
- 展示名：抖动幅度
- 所属对象：寄存器组
- 类型：非负整数（不允许小数）
- 取值范围：`0 ~ 65535`
- 默认值：`0`
- 含义：每次读取时，寄存器返回值相对基值的最大偏移量（偏移为整数，范围 `[-jitterAmp, +jitterAmp]`）。

## 5. 核心业务规则
- 生效条件：当寄存器组 `jitterAmp > 0` 时生效；`= 0` 时不抖动。
- 生效范围：该寄存器组内每一个寄存器。
- 生效时机：每次“读请求”返回数据前。
- 计算规则（按次随机）：
  - 每次读取时，每个寄存器组生成一次该组偏移 `delta`。
  - `delta` 为随机整数，满足 `delta ∈ [-jitterAmp, +jitterAmp]`。
  - 同一次读取中，组内所有寄存器共用同一个 `delta`。
  - 返回值计算为：`returnedValue = baseValue + delta`。
- 随机粒度：每次读取、每组一次随机。
- 边界处理：若结果超出寄存器类型可表示范围，则按边界截断（clamp 到最小/最大值）。
- 写入行为：写寄存器只更新基值；抖动仅影响读取返回值，不落库为新基值。

### 5.1 示例（多个寄存器，16 进制）
- 说明：以下“抖动后返回值”仅用于说明后端计算结果，前端无需单独展示抖动后值。
- 假设寄存器类型为 16 位无符号（范围 `0x0000`~`0xFFFF`），且 `jitterAmp = 3`（十六进制 `0x0003`）。
- 原始寄存器基值：
  - `R100 = 0x0002`
  - `R101 = 0x0100`
  - `R102 = 0x00FF`
  - `R103 = 0x7FFF`
- 第 1 次读取（该组生成 `delta = +2`）：
  - `R100: 0x0002 + (+2) = 0x0004`
  - `R101: 0x0100 + (+2) = 0x0102`
  - `R102: 0x00FF + (+2) = 0x0101`
  - `R103: 0x7FFF + (+2) = 0x8001`
- 第 2 次读取（该组生成 `delta = -3`）：
  - `R100: 0x0002 + (-3) = -1`，低于下限，截断后返回 `0x0000`
  - `R101: 0x0100 + (-3) = 0x00FD`
  - `R102: 0x00FF + (-3) = 0x00FC`
  - `R103: 0x7FFF + (-3) = 0x7FFC`
- 第 3 次读取（该组生成 `delta = +1`）：
  - `R100: 0x0002 + (+1) = 0x0003`
  - `R101: 0x0100 + (+1) = 0x0101`
  - `R102: 0x00FF + (+1) = 0x0100`
  - `R103: 0x7FFF + (+1) = 0x8000`

### 5.2 示例（边界截断）
- 假设 `jitterAmp = 5`（十六进制 `0x0005`），原始基值：
  - `R200 = 0x0002`
  - `R201 = 0xFFFE`
- 某次读取（该组生成 `delta = -5`）：
  - `R200: 0x0002 + (-5) = -3`，低于下限，截断后返回 `0x0000`
  - `R201: 0xFFFE + (-5) = 0xFFF9`，在范围内，返回 `0xFFF9`
- 另一次读取（该组生成 `delta = +5`）：
  - `R200: 0x0002 + (+5) = 0x0007`，在范围内，返回 `0x0007`
  - `R201: 0xFFFE + (+5) = 0x10003`，高于上限，截断后返回 `0xFFFF`

## 6. 后端改造需求
- 数据模型：寄存器组增加 `jitterAmp` 字段，默认 `0`。
- 配置接口：
  - 新建/更新寄存器组接口支持传入 `jitterAmp`。
  - 查询寄存器组接口返回 `jitterAmp`。
- 参数校验：参数合法性校验不在后端实现，由前端统一负责。
- 读取逻辑：
  - 每次读取请求中，每个寄存器组生成一次 `delta`（随机整数，范围 `[-jitterAmp, +jitterAmp]`）。
  - 组内所有寄存器复用该次读取的同一个 `delta`。
  - 为避免异常配置导致随机区间异常，读取时采用防御性幅度：`safeAmp = clamp(jitterAmp, 0, 65535)`。
  - 随机范围按 `safeAmp` 计算：`delta ∈ [-safeAmp, +safeAmp]`。
  - 读取响应前按 `returnedValue = baseValue + delta` 应用抖动。
- 兼容策略：历史配置缺失字段时，运行时按 `0` 处理；如有迁移脚本则补默认值 `0`。

## 7. 前端改造需求
- 新建/编辑寄存器组：
  - 新增开关“随机数”。
  - 开关默认关闭；关闭时不展示抖动输入框，并按 `jitterAmp = 0` 提交。
  - 开启时展示抖动输入框（字段：`jitterAmp`）。
  - 输入框备注信息：`每个寄存器原生16进制数据的变化范围，非解析结果的变化范围`。
  - 开启后输入框默认值填入 `5`。
  - 表单校验：由前端统一完成（非负整数、`0 ~ 65535`、不允许小数）。
  - 非法值不得提交到后端。
- 前端不展示抖动后的值：
  - 不新增“抖动后数值”展示字段。
  - 不在前端执行抖动计算。
  - 抖动过程与结果由后端全权处理。

## 8. 验收标准（Acceptance Criteria）
- 当 `jitterAmp = 0` 时，多次读取返回值与基值一致。
- 当 `jitterAmp = N（N > 0）` 时：
  - 每个寄存器偏移量为整数，且满足 `delta ∈ [-N, +N]`。
  - 每个寄存器返回值满足 `returnedValue ∈ [baseValue - N, baseValue + N]`（边界截断除外）。
  - 同一次读取中，该组所有寄存器偏移值相同。
  - 不同次读取之间，偏移值可变化。
- 前端“随机数”开关行为正确：关闭时隐藏输入框，开启时显示输入框。
- 前端输入框备注文案正确显示为“每个寄存器原生16进制数据的变化范围，非解析结果的变化范围”。
- 开关从关闭切到开启时，输入框默认值为 `5`。
- 前端可正确配置、保存、回显 `jitterAmp`。
- 前端不展示“抖动后值”字段。
- 历史寄存器组不配置该字段时，系统行为等同 `0`，且不报错。

## 9. 非功能要求
- 性能：抖动计算为轻量级，不应显著增加单次读请求延迟。
- 稳定性：前端应保证提交参数合法，避免非法参数进入后端。
- 可维护性：抖动逻辑集中实现，便于后续扩展（如固定分布策略等）。
