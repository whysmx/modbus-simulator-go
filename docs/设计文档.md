# Modbus 仿真器设计文档

## 项目概览

- 项目名称：Modbus 仿真器
- 开发语言：Go 1.22+
- 部署方式：本地部署，单一可执行文件

## 技术栈

- 后端：Go（net/http + embed）
- 前端：原生 HTML/CSS/JavaScript
- 存储：纯内存，无外部依赖

## 简化约束（从简可用）

- 默认信任本地环境，不做鉴权与权限隔离
- 校验以“前端为主”，服务端不做复杂校验与修正
- 并发一致性不保证：HTTP 写与 TCP 读允许短暂不一致
- 地址语义为逻辑地址（1-based），不做 PDU 0-based 映射修正
- 字节序/位序固定为常见默认，不提供可配置选项

## 协议支持

- Modbus TCP
- Modbus RTU over TCP
- Modbus TCP 侧仅支持读功能码（01-04）
- 数据修改通过 HTTP API 完成

## 系统架构

```
Web 前端 ←→ HTTP API ←→ 业务服务 ←→ 内存存储
                          ↓
                   TCP 服务 ←→ Modbus 客户端
```

### 核心模块

- Web 前端：设备树、寄存器编辑、手动保存
- HTTP API：连接/从机/寄存器的 CRUD
- TCP 服务：多端口监听，读功能码仿真
- 数据层：三层结构（connections → slaves → registers）

## 数据模型

### ProtocolType

- 0：Modbus RTU over TCP（默认）
- 1：Modbus TCP

### Connection

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 32 位无横杠 UUID |
| name | string | 连接名称（唯一） |
| port | number | 端口号（默认从 1502 开始递增，可配置起始端口） |
| protocolType | number | 协议类型：0/1 |

### Slave

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 32 位无横杠 UUID |
| connId | string | 所属连接 ID |
| name | string | 从机名称（同连接下唯一） |
| slaveAddr | number | 从机地址（1-247） |

### Register

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 32 位无横杠 UUID |
| slaveId | string | 所属从机 ID |
| startAddr | number | 起始逻辑地址（用于类型判定） |
| hexData | string | 连续寄存器的 16 进制字符串（大写、无 0x） |
| names | string | 逗号分隔的寄存器名称（可选） |
| coefficients | string | 逗号分隔的显示系数（可选，默认 1.0） |

### RegisterType（按地址区间）

| 类型 | 功能码 | 地址范围 | 数据格式 |
|------|--------|----------|----------|
| Coil | 01 | 00001-09999 | 位型，每 2 hex = 1 字节 = 8 位 |
| DiscreteInput | 02 | 10001-19999 | 位型，每 2 hex = 1 字节 = 8 位 |
| InputRegister | 04 | 30001-39999 | 寄存器型，每 4 hex = 1 个 16 位寄存器 |
| HoldingRegister | 03 | 40001-49999 | 寄存器型，每 4 hex = 1 个 16 位寄存器 |

### 数据关系

```
Connection (1) ──→ (N) Slave (1) ──→ (N) Register
```

- 删除 Connection 时级联删除其下 Slave 与 Register
- 删除 Slave 时级联删除其下 Register

### HexData 规则

- 寄存器型（FC03/04）：长度为 4 的倍数
- 位型（FC01/02）：长度为 2 的倍数
- 仅允许十六进制字符（0-9A-F），前端校验并统一转为大写

### 内存存储结构

- 主表：connections / slaves / registers
- 索引：port→connection、connection→slaves、slave→registers
- 地址重叠检测需按 slave + 寄存器类型做区间判定

## HTTP API 规范

### 路径参数约定

- `{id}`：Connection.id（UUID）
- `{slaveId}`：Slave.id（UUID）
- `{regId}`：Register.id（UUID）
- Modbus 从机地址用字段 `slaveAddr` 传递，不作为路径参数

### 接口列表

```
GET    /api/connections/tree
POST   /api/connections
PUT    /api/connections/{id}
DELETE /api/connections/{id}

POST   /api/connections/{id}/slaves
PUT    /api/connections/{id}/slaves/{slaveId}
DELETE /api/connections/{id}/slaves/{slaveId}

GET    /api/connections/{id}/slaves/{slaveId}/registers
POST   /api/connections/{id}/slaves/{slaveId}/registers
PUT    /api/connections/{id}/slaves/{slaveId}/registers/{regId}
DELETE /api/connections/{id}/slaves/{slaveId}/registers/{regId}
```

### 响应规范

- 成功：200 / 201 / 204
- 失败：400（校验失败）/ 404（资源不存在）
- 错误格式：`{ "error": "具体错误描述" }`

### 地址重叠规则（简单版）

- 同一 Slave 下，先按 `startAddr` 区间归类寄存器类型
- 同一寄存器类型内，地址区间不得重叠
- 区间计算：
  - 寄存器型：`[startAddr, startAddr + count - 1]`，`count = hexData.length / 4`
  - 位型：`[startAddr, startAddr + count - 1]`，`count = (hexData.length / 2) * 8`

### 数据加载策略

1. 初始加载：`GET /api/connections/tree` 获取连接 + 从机
2. 展开从机：首次展开时获取寄存器列表
3. 前端按 `startAddr` 做类型分类

## 前端设计

### 页面布局

- 左侧：设备树（连接 → 从机 → 寄存器类型）
- 右侧：寄存器表格（标签页显示）
- 顶部：保存按钮（手动提交）

### 设备树规则

- 连接、从机、寄存器类型的增删改入口
- 寄存器类型节点点击后创建标签页

### 寄存器表格（关键点）

- 单一真值源：Hex/Bit 作为最终存储值
- 编辑任一列后，换算回写 Hex/Bit，再更新其他展示列
- 编辑后标记脏状态，保存后清除
- 无效转换显示 NA

### 浮点数显示

- 每个浮点数跨 2 个寄存器
- 滑动窗口展示，精度保留 3 位

### 前端校验（必做）

- `startAddr` 必须落在四种合法区间之一
- `hexData` 必须为十六进制字符，长度符合类型要求
- 位型编辑不得越界

### 前端缓存策略

- 寄存器数据按 slaveId 缓存
- 增删改后标记失效并重新拉取
